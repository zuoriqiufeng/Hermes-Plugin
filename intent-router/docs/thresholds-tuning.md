# 阈值调参手册

三个阈值不是魔法常数，但**也不能凭感觉改**。默认值（`min_score=0.62`、`margin=0.15`、
`min_evidence=2`）只是起点，正确做法是：先用 shadow 采真实流量，再回来动它们。

## 1. 三个阈值分别在拦什么

| 阈值 | 拦掉的失败模式 | 调松的代价 | 调紧的代价 |
|---|---|---|---|
| `min_score` | 证据太弱还想表态 | 弱证据也能通过 → 误判变多 | 覆盖下降，残差都推给第三层 |
| `margin`（top1-top2） | 两个意图势均力敌时硬选一个 | 歧义输入被强行归类 | 稍偏的输入也不表态 |
| `min_evidence` | 单凭一个关键词就下结论 | 单证据即表态（最危险的一档） | 覆盖下降 |

**先看 `min_evidence` 再看其他两个**。它拦的是本插件最典型的一类错判：
「消息里出现了『同步』，就判成同步类问题」。默认 2 表示要求两路独立证据
（关键词 / BM25 / 实体 三类里至少两类），这一条比分数阈值更能决定观感。

## 2. 用标注语料先定一版：`/intent tune`

```
/intent tune
语料 63 条（正 43 / 负 20）——按「错判+误报」升序、覆盖率降序取前 8 行：
  min_score margin evidence | 覆盖率  本地精度  第一层精度  错判 误报
      0.70   0.25        2 |   97.7%    100.0%      100.0%     0    0
  ...
当前配置：min_score=0.62 margin=0.15 min_evidence=2
当前配置已在最优档：这 50 组阈值在语料上**等价**（错判/覆盖率完全相同）
```

怎么读这张表：

- **错判/误报列必须是 0**。只要不是 0，说明词表或规则有问题，**不要靠调阈值掩盖**
  （先把错例补进语料，再修词表/规则/否决模式）。
- 覆盖率 = 正样本被本地两层正确解决的比例。它是「省下多少钱」的代理指标。
- 如果多行**等价**（错判与覆盖率完全相同），说明这些阈值在语料上不可区分——语料规模
  与分数离散度决定了分辨率。此时**取更保守的一侧**（更严格），把宽松档留给有数据支撑的场合。

## 3. 用真实流量校准（shadow 模式的意义）

shadow 档位下每条消息都会落一行决策日志（含「假如放开会做什么」的反事实动作），
行为零改动。跑一段时间后：

```bash
/intent stats 2000          # 层分布 / 表态率 / 第三层占比 / 延迟分位 / 注入字符量
```

关注四个信号：

| 信号 | 含义 | 处置 |
|---|---|---|
| `gate_reasons` 里 `insufficient_evidence` 占比高 | 词表覆盖不足（有词命中但没第二路证据） | 给对应意图补**范例句**（BM25 那一路），比加关键词更安全 |
| `gate_reasons` 里 `margin_too_small` 占比高 | 意图之间本身重叠（词表设计问题） | 看 `candidates` 里谁常和谁并列，用 `veto_patterns`/`exclude` 拆开 |
| `skipped.follow_up` 很高 | 追问护栏在正常工作 | 无需处理（这类输入本就不该识别） |
| 顶部意图里出现 `(none)` 很多 | 大量输入判不出来 | 属正常（开放式问题）；只有在你预期该覆盖时才补词表 |

> 关键：**不要为了让 `(none)` 变少而调松阈值**。判不出来本身不是缺陷；
> 判错才是。

想看「为什么这条没认出来」的**原始依据**，直接看插件日志（`/intent log 50`）——
把 `log_level` 临时设成 `debug` 后，未表态的输入会连同候选分数与门控原因一起落盘
（默认 `info` 不记这些，避免日常刷量）。详见 [logging.md](./logging.md)。

## 4. 用误判反馈闭环

会话里遇到判错，直接：

```
/intent why                 # 看这次判成了什么、什么证据、门控为什么放行
/intent wrong <正确意图id>   # 落一条修正记录到 corrections.jsonl
```

然后把那条输入补进 `data/corpus/regression.yaml`（`corrections.jsonl` 里有原文预览与
预测值，便于回填）。补完跑：

```bash
python3 -m pytest tests/test_corpus_regression.py -q
```

**语料是唯一的防回归网**：改词表、改规则、调阈值之后，只要这条测试还是绿的，
已知行为就没被改坏。

## 5. 什么时候该动词表而不是阈值

| 现象 | 更该做的事 |
|---|---|
| 某个说法总认不出来 | 给该意图加**范例句**（走 BM25），而不是降 `min_score` |
| 某个说法被误认成别的意图 | 给被误认的意图加 `veto_patterns`，或用 `exclude` 摘掉过泛词条 |
| 某类消息总被误判成 X | 检查 X 的词表里有没有「到处都出现的词」（如 `报错/失败`）→ `exclude` 摘掉 |
| 意图之间总并列 | 说明两个意图的边界本身没定清楚 → 先合并或明确边界，再调 `margin` |

一句话：**阈值管「敢不敢说」，词表管「说得对不对」**。用阈值去补词表的漏洞，
结果只会是覆盖与精度一起掉。
