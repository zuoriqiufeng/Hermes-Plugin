# 设计原理（为什么是这三层、为什么动作只做到这一步）

## 1. 问题：意图识别被当成模型的事

原状是「每个用户输入都让大模型判一次意图」。两个代价：

- **慢**：多一次模型往返（还要加上推理 token 的生成时间）；
- **贵**：意图判断本身要消耗 token，而它换来的往往只是一个「该用哪个工具」的路由结论。

而这类判断里有很大一部分是**确定性**的：整句就是一个错误码、一句「你好」、
一句「继续」——这些不需要模型，需要的是把已知的判据写成代码。

## 2. 三层的信息经济学：漏斗越往下越贵

| 层 | 单位成本 | 覆盖什么 | 本插件实测 |
|---|---|---|---|
| 第一层 正则 | ~微秒 | 意图形状明确的输入（纯错误码、命令式短语、寒暄、追问） | 语料 43 条正样本里 14 条在此层解决 |
| 第二层 词典 + BM25 | ~百微秒 | 换了个说法的同一件事 | 再解决 28 条 |
| 第三层 大模型 | 一次模型调用 | 前两层不敢下结论的残差 | 剩 1 条交给它 |

关键在于**门控**而不是打分：会「不敢下结论」的识别器才有资格上关键路径。
所以第二层用三重门控（分数阈值 / top1-top2 差距 / 独立证据条数），任何一条不过
就不表态——宁可让主模型自己判，也不要拿着半信半疑的结论去指挥它。

## 3. 平台约束决定了动作层的上限（重要）

设计前先把 Hermes 的能力边界查清楚（源码位置都标了，便于复核）：

- `pre_llm_call` 每轮触发，返回 `{"context": str}` 会被拼进**当前用户消息**
  （`agent/turn_context.py:658-712`、`:975`）——这是插件唯一能「往对话里塞东西」的通道，
  且是一次性的（不污染后续轮次）。
- `llm_request` 中间件可以**整体替换** provider 请求（含 `tools`），上下文带 `api_call_count`
  （`hermes_cli/middleware.py:88-99`、`agent/turn_api_request.py:148-162`）。
- `pre_llm_call` 属于 30 秒有界 hook（`hermes_cli/plugins_dispatch.py:41-45`）——
  所以插件自己的执行必须有更短的硬超时，不能指望宿主兜底。
- **对普通文本消息，没有「受支持的」零模型调用回复通道**：只有斜杠命令能零 LLM 直达用户；
  想凭空造一个回复，得用未公开的 `llm_execution` 中间件伪造 provider 响应对象。

最后一条是整个设计的转折点。既然不能「不调模型」，收益就必须换个地方拿：

1. **少一轮工具循环**：act 档位替模型把只读工具调好、结果注入上下文，模型一次请求即可作答
   （原先是「判意图 → 选工具 → 调工具 → 读结果 → 再作答」的多轮往返）。
2. **少带无关工具**：按意图裁剪本轮工具面，省掉无关工具 schema 的固定开销。
3. **少花路由推理**：意图直接写明，模型不必在「这属于哪类问题」上花 reasoning token。

**刻意不做**：`llm_execution` 伪造响应。它依赖内部对象形状，Hermes 一升级就可能失效，
而这类插件的故障代价是「对话答非所问」，不值这个险。

## 4. 为什么 act 的准入是五重闸

直连工具是本插件唯一会「做事」的能力，也是对系统影响最大的一处，所以权限收紧到极致：

```
意图声明 safe_auto  ∧  工具在白名单  ∧  auto_enabled  ∧  判定来自本地两层  ∧  requires 齐全
```

- 前两条把「哪些操作可以被自动触发」的决定权交给**人**（词表作者 + 运维），而不是代码；
- 第三条是总闸，默认关；
- 第四条是安全底线：**模型判断不允许触发自动执行**（`tier3_allow_act` 默认 false）。
  一个廉价小模型的判断精度不足以承担副作用；
- 第五条防「参数取不到硬调」；再加历史去重防相邻轮重复调用。

执行期还有硬超时（daemon 线程 + Event，超时即放弃——工具按契约只读，放弃是安全的）
与结果截断；工具输出按「数据非指令」注入并清洗分隔符，防止工具内容越界伪造指令段。

## 5. 不确定就闭嘴（这条比识别率重要）

插件的失败模式有两种，代价完全不对称：

- **漏识别**（该识别没识别）：主模型照旧自己判断，只是没省下钱 → 可接受；
- **错识别**（不该表态却表态）：注入错误的意图提示，或**调错工具** → 会误导回答、甚至产生副作用。

所以整套设计偏向漏识别：追问护栏直接跳过、三重门控宁可闭嘴、否决模式一票取消候选、
`min_evidence=2` 拒绝「单凭一个关键词就下结论」。语料回归也把这一点写死：
**本地两层表态了就必须正确**（precision 100%），覆盖率只设下限不设上限。

## 6. 与既有插件的关系

- 与 `i2stream-bkn`：**不跨仓 import**，只通过 `tools/gen_lexicon.py` 生成带源哈希的词表快照。
  对方重构不会打断本插件加载；源词表变了 `/intent doctor` 会报漂移。
- 与 `hermes-dag`：本插件发布 `intent-router:classified` 事件，给 DAG 预留的「进图闸门
  / triage 前置裁决」留出零耦合接入点（本版不实现闸门，只发事件）。
- 与 `reasoning-bridge`：同为观察者思路的邻居——它把思考过程落 JSONL 给外部消费，
  本插件把决策落 JSONL 给调参消费。
